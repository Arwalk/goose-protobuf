# 0016: edition 2024 is supported

- Status: accepted
- Date: 2026-11-06
- Bead: gpb-ky7.10
- Toolchain: Goose v2026.3, protoc 36.2, linux-x64
- Builds on: [0014](0014-protoc-range.md) (protoc range)

## Question

Files of edition 2024 were refused, by protoc on the plugin's behalf. What does the
edition change, and can the plugin take it?

## What the edition changes

Compared with edition 2023, from `descriptor.proto` and
`protoc --edition_defaults_out`:

| Change | Effect on the plugin |
|---|---|
| The defaults of `field_presence`, `enum_type`, `repeated_field_encoding`, `utf8_validation` and `message_encoding` | None: all five are unchanged, and they are all the wire format reads |
| `enforce_naming_style` defaults to `STYLE2024`, and `default_symbol_visibility` to `EXPORT_TOP_LEVEL` | None: protoc enforces both, and a file that breaks them never reaches the plugin |
| `export` and `local` on a type | None: types are generated the same |
| `import option`, for a file only needed for custom options | None: it is not a dependency in the request, so the generated file does not import it |
| `ctype` and `java_multiple_files` are removed, and `string_type` is added for C++ | None: the plugin reads none of them |

So the change is one number in the plugin's response, and the table it is tested
against.

## Evidence

- `tests/protos/editions_2024.proto` uses all of the above. A golden and a round trip
  through protoc and Python hold it.
- **The conformance suite has no edition 2024 message.** `--maximum_edition 2024` runs
  exactly what 2023 does: 2832 successes either way. CI passes that flag, but it shows
  only that nothing regressed.
- So the real test was run once, by hand: the suite's `TestAllTypesEdition2023` recompiled
  as edition 2024, with `ctype` and `java_multiple_files` taken out and legacy names
  allowed, as the edition requires. It gave the same 2832 successes, and with
  recommended tests the same one listed failure, so the failure lists did not grow.

## Decision

**The plugin takes edition 2024.** Edition 2024 files need protoc 32.0 or later, which is
when protoc began to take them. Older releases in the range of decision 0014 still refuse
such files with their own clear error, and still take everything else, so the range does
not change. `scripts/protoc_versions.sh` leaves the 2024 tests out below 32.

Generated code for edition 2024 uses the same public names, so this is a minor by
decision 0012.

Edition 2026 stays refused. protoc 36.2 takes it and asks the plugin, which gives a clear
error. Its changes have not been looked at.

## If the suite gains a message

A later protobuf release may add an edition 2024 message to the suite. Then the testee
should handle it, and the one-off above is no longer needed.
